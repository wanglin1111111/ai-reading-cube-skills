> 本文件用于校准 knowledge-alchemy 的 description 触发率，方法对齐 agentskills.io/skill-creation/optimizing-descriptions。
> **测试方法说明**：用"全新上下文子代理做盲判路由"作 trigger_rate 的代理指标——给干净上下文的代理看 4 个 Skill 的 description + 1 条查询，判路由到哪个。这测的是"description 对仔细阅读者是否可辨别"，是触发可靠的必要条件；真实生产触发率还依赖平台相似度匹配算法，无法在对话内完全复现。

这些查询共享关键词（划线、笔记、整理、结构化、知识、卡片），但真实意图不是把划线炼成知识体系，应路由到相邻 Skill 或 NONE。

| N6 | 这本书作者是谁 | 事实查询 | NONE |

> **N8「画人物关系图」是已知边界案**：前序测试中 book-dialogue v1.2 修补后该查询从 A 转向 C，但 C 的输入是划线/摘录、并非整本书人物谱系——严格说 C 也不是完美匹配。本轮重点验证此边界是否需在 C 的 description 里澄清。

### 测试详情（v1.0，2026-08-10）

**方法**：综合 batch 盲判（24 条查询覆盖 3 个 skill，随机化顺序）+ 边界案 N8 各轮重测。共 28+ 次独立子代理判定。

**本 skill 相关查询（应触发的 T1-T7）**：划线整理结构化笔记/建知识库/卡片笔记法/高亮提炼连网——均 HIGH 置信判 C，0 失败。

**关键边界案 N8「《百年孤独》人物关系太乱，画个图」**：
- 前序测试（book-dialogue v1.2 前）：该查询曾过度触发到 book-dialogue(A)。
- book-dialogue v1.2 修补后：曾一度落到 C（因 C 产出含"关系图"）。
- 本轮（含 2 次独立重测）：**稳定为 NONE**——判别理由"A 明确不产图，C 的关系图只针对划线/概念互链、与整本书人物谱系不匹配"。
- **结论**：N8 不再误触到 C。C 的 description 当前措辞（输入=一批划线高亮，输出=概念间互链/主题索引）已足够划清与"整本书人物关系图"的边界，**无需额外修改**。若未来出现"把这本书的概念画成关系图"这类查询（输入确实是书的概念而非人物谱系），则属 C 的合理范围。

**结论**：knowledge-alchemy 的 description 触发边界清晰，无过度触发、无漏触发。
