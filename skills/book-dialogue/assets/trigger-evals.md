# 触发可靠性评估清单 (trigger-evals)

> 本文件用于**校准 book-dialogue 的 description 触发率**，方法对齐 agentskills.io/skill-creation/optimizing-descriptions 官方方法论。
> 用法：把下列每条查询当作真实用户输入，在新会话里发送，观察本 Skill 是否被触发。每条跑 3 次，trigger_rate ≥ 0.5 算通过。

## 评估方法（官方要点）

- **查询集**：约 20 条，分为 should-trigger（应触发）与 should-not-trigger（不应触发）。
- **负例用 near-miss**（共享关键词但实际需求不同），不要用明显无关的——后者测不出边界。
- **每条跑 3 次**，统计触发率。
- **6:4 切分**：前 60% 为 train 集（用来改 description），后 40% 为 validation 集（用来判断是否泛化、有无过拟合）。
- **迭代**：通常 5 轮足够。改 description 时找"失败查询所属的一般类别"，不要直接把失败查询的原话塞进 description（会过拟合）。

## Should-not-trigger（不应触发，10 条，均为 near-miss）

这些查询共享关键词（书名、读、聊、理解），但真实意图**不是**对谈式精读，本 Skill 不应触发——应路由到相邻 Skill 或直接处理。

| # | 查询 | 真实意图 | 应路由到 |
|---|---|---|---|
| N1 | 把这段《活着》的读后感做成小红书卡片 | 生成社媒内容 | reading-card-crafter |
| N2 | 帮我写一篇《百年孤独》的书评 | 代写文章 | read-to-write |
| N3 | 我把这些《思考快与慢》的划线整理成笔记库 | 知识结构化 | knowledge-alchemy |
| N4 | 《三体》的作者是谁，哪年出版的 | 事实查询 | 直接答（无需 Skill） |
| N5 | 帮我找几本和《百年孤独》类似的书 | 书目推荐 | 直接答/其他 |
| N6 | 把这段《红楼梦》的英文翻译成中文 | 翻译 | 直接答 |
| N7 | 这本书的 PDF 在哪下载 | 资源获取 | 直接答（无法做） |
| N8 | 帮我给读书会写个《活着》的讨论提纲 | 生成提纲 | read-to-write 或直接 |
| N9 | 《百年孤独》人物关系太乱，画个图 | 信息可视化 | 直接答 |
| N10 | 这段读后感帮我润色一下发出去 | 文案润色 | reading-card-crafter |

> **near-miss 的价值**：N1/N2/N3/N8/N10 都带"书/读/读后感"等关键词，容易误触发。如果它们被误触发了，说明 description 的"不做什么"边界要补强（但只在误触发时才补，不要预先堆砌）。

## 迭代记录（每次改完 description 在此记一笔）

> **测试方法说明**：本评测用"全新上下文子代理做盲判路由"作为 trigger_rate 的代理指标——给干净上下文的代理看 4 个 Skill 的 description + 1 条用户查询，判路由到哪个。这测的是"description 对仔细阅读者是否可辨别"，是触发可靠的必要条件；真实生产触发率还依赖平台相似度匹配算法，无法在对话内完全复现，特此说明。

### 测试详情（v1.1 → v1.2）

**Phase 1 盲判（20 条，随机化顺序）**：18/20 正确。2 个 validation 失败均为 book-dialogue 过度触发（把"生成结构化产物"误揽）。
- N9《百年孤独》人物关系太乱，画个图 → 期望 NONE，4 次判定 A×3 / C×1
- N8 帮我给读书会写个《活着》的讨论提纲 → 期望 D/NONE，4 次判定 A×2 / NONE×2

**Phase 2 失败项 3× 重测**：确认 Q10/Q16 的过度触发稳定（非噪声）。

**Phase 3 train/validation 归属**：train(T1-T7+N1-N5)=12/12 全过；失败均在 validation(T8-T10+N6-N10)。按规范"只用 train 改 description"，严格说无 train 依据；但 Q10 的 3/4 过度触发是真实边界模糊，故做一处**一般化**（非关键词）澄清。

**Phase 4 v1.2 重测**：
- N9：A 3/4 → **A 0/2**（改判为 C×2）→ book-dialogue 过度触发消除
- N8：A 2/4 → **NONE 2/2** → 稳定为 NONE
- train 回归抽查 Q5(帮我读)→A·HIGH、Q8(划线整理)→C·HIGH，无回归

### 已知遗留（非本次评测范围，记为后续待办）
- N9「画人物关系图」v1.2 后落到 knowledge-alchemy(C)，但 C 的输入是划线/摘录、非整本书人物谱系——严格说 C 也不算完美匹配。这是 **knowledge-alchemy 的 description 边界问题**，待其单独评测时处理。

> 运行评估后，把结果填进来。若 train 集有失败，找失败查询的意图类别，在 description 里补上该类别的触发词；再用 validation 集验证有没有泛化。
